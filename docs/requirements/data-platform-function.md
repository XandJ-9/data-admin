“从业务数据源到数据仓库落地”的整条链路，清晰地划分为 **5 个核心里程碑步骤**。

---

### 第一步：破冰与连接 (Connection & Discovery)
**目标：让平台认识并连通源头数据。**

*   **业务动作：** 平台管理员在“数据源管理”界面，录入业务系统（如 ERP、电商后台）的 MySQL/PostgreSQL 连接信息。
*   **平台底层运作：**
    1.  保存连接配置到 `DataSource` 表（密码加密）。
    2.  触发“连通性测试”。
    3.  **元数据嗅探：** 触发数据采集，去源库里执行 `show tables`，把业务系统里有哪些表、哪些字段“爬”回平台的元数据库（准备为后续的自动补全和数据地图做储备）。

### 第二步：数据搬运入仓 (Data Integration -> STG/ODS 层)
**目标：原汁原味地把数据抽过来，也就是“ODS 以下是 ETL 的领地”。**

* **业务动作：** 数据集成工程师打开**“向导式同步表单”**，选择源头 MySQL 的 `order_info` 表，映射到数仓的 `ods_order_info` 表，配置为“每天凌晨 1 点全量覆盖”。

  *注意* ：对于多租户分散在多个数据源的异源同构数据，一般可以将数据集成到STG数据缓冲层，按照数据源分区，然后聚合到ODS层。

*   **平台底层运作：**
    1.  前端提交表单。
    2.  在统一的 `Task` 表中生成一条记录，`task_type = 'DATA_SYNC'`，并将映射规则以 JSON 存入 `task_config`。
    3.  调度引擎按时唤起，执行真正的同步动作（如调用 DataX 或直接执行类似 `INSERT INTO ods... SELECT ... FROM mysql...` 的底层操作）。
    4.  **结果：** 数据成功降落在数仓的最底层（ODS 层，即贴源层），此时数据依然是“原始的、未经加工的”。

### 第三步：加工与建模 (Data Development -> DWD/DWS/ADS 层)
**目标：将原始数据转化为有业务价值的指标，这是“ODS 以上的数据开发领地”。**

*   **业务动作：** 数据分析师打开你的 **“Web IDE 工作台”**，新建一个 SQL 脚本。
    *   左侧树形目录清晰分类：`DWD (明细层)` -> `DWS (汇总层)` -> `ADS (应用层)`。
    *   在编辑器中编写 SQL：从 ODS 层读取订单数据，清洗掉测试数据（NULL 值），按照“每日、每门店”进行 `GROUP BY` 聚合，最终写入 DWS 层的汇总表。
*   **平台底层运作：**
    - 前端调用 API，在 `Task` 表中生成一条记录，`task_type = 'SQL_COMPUTE'`，SQL 代码存入 `task_config`。

### 第四步：编排与运维 (Orchestration & DataOps)
**目标：让这些脚本每天自动化、按顺序地无错运行。**

*   **业务动作：** 用户在任务配置抽屉里，把“步骤三的 SQL 任务”连在“步骤二的同步任务”之后。
*   **平台底层运作：**
    1.  平台在 `TaskDependency` 表中写入依赖关系，形成一张有向无环图（DAG）。
    2.  调度核心（Scheduler）发挥作用：每天凌晨，同步任务（Sync）成功后，状态流转为 `SUCCESS`，立即触发下游的 SQL 汇总任务，生成新的 `TaskInstance` 并投入运行。
    3.  一旦报错，平台捕获异常日志，状态变为 `FAILED`，并在前端的运维拓扑图上将该节点标红。

### 第五步：资产化与服务 (Assetization & Service)
**目标：让加工好的数据被业务方搜索到、用起来。**

*   **业务动作：** 
    *   业务方打开“数据地图”，搜索“门店日营收”，平台立刻展示出 DWS 层的那张表，以及它的字段含义。
    *   前端自动渲染出血缘图：`业务库 MySQL -> ODS -> DWD -> DWS` 一目了然。
    *   甚至一键生成 API，供前端报表直接调用（数据服务层）。

---

### 阶段性总结与架构反思

回顾这条流水线，你会发现我们之前设计的架构完美地支撑了这 5 个步骤：
*   **底层极简：** 步骤二（表单）和步骤三（代码）在后端其实全都在读写同一张 `Task` 表。
*   **体验极致：** 对于“干力气活”的步骤二，给用户最简单的下拉框；对于“做细致活”的步骤三，给用户最专业的 IDE 编辑器。
*   **低成本治理：** 没有专门做一个庞大的治理系统，而是在“步骤三保存时”和“步骤五搜索时”就把规矩定好了。
