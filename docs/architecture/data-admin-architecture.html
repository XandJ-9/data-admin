Data Admin Architecture

统一数据管理平台架构图

当前项目以 Django Apps + Vue3 前端为主干，按连接与发现、数据集成、数据开发、任务运维、资产与服务五个阶段组织。 现阶段最重要的设计原则是：业务任务定义留在来源模块，统一任务台账、调度索引和执行实例收敛到 datatask。

当前建设口径

  • 先完成任务定义真源与统一任务运维纳管。
  • dataasset 作为语义锚点，dataservice 作为消费出口。
  • 通过 source handler / facade 降低模块间反向依赖。

模块职责矩阵

按当前主干实现与 ADR 口径整理出的职责边界。

datasource Connection & Discovery

维护数据源、连接测试、库表字段发现，并通过采集任务把源端元数据同步到资产侧。

dataintegration Data Integration

维护贴源同步任务、源目标映射和入仓策略；执行实例统一进入 datatask。

datadev Data Development

承载模型设计、SQL/Python 加工作业、开发态版本与发布前治理卡点。

datatask Orchestration & DataOps

作为统一任务镜像、依赖、调度、执行和 TaskInstance 实例中心，不直接持有业务真身。

dataasset Assetization

沉淀资产目录、元数据、标签、血缘与治理信息，是平台统一语义锚点。

dataservice Service

提供查询、接口、报表、导出和调用审计能力，是数据消费出口。

system / monitor Control Plane

负责认证、菜单、角色、操作日志、服务器监控与平台基础控制面。

executors / dbutils Foundation

统一数据源执行器、数据库访问适配、SQL 查询执行和底层连接封装。

主链路

平台从接入数据源到形成数据服务的推荐流向。

连接与发现

在 datasource 维护连接，完成连通性测试、库表字段发现和采集任务定义。

贴源入仓

在 dataintegration 配置源表、目标表、同步策略和字段映射。

建模加工

在 datadev 设计模型，编写 SQL/Python 作业，发布稳定开发事实。

统一运维

datatask 统一纳管任务镜像、依赖、调度和执行实例。

资产与服务

dataasset 形成语义资产，dataservice 将 ADS 或查询能力转成接口与报表。

架构建议

结合当前代码评审，建议优先补齐这些平台化边界。

权限基线

后端 action 需要真正绑定菜单 perms、角色和数据权限，避免只靠前端菜单隐藏。

生产配置

拆分 dev/prod settings，密钥、数据库、DEBUG、ALLOWED_HOSTS、Channel Layer 全部环境化。

查询治理

dataservice 建议补参数化、只读连接、SQL 超时、最大行数、导出限制与审计告警。
