# monitor 模块架构

## 模块定位

`apps.monitor` 负责平台运行监控、操作日志和在线用户等基础运维能力。

它是系统运维辅助模块，不承载数据任务调度和任务执行历史；任务运行状态归 `datatask.TaskInstance` 管理。

## 核心职责

1. 记录操作日志。
2. 记录登录和在线状态相关信息。
3. 提供服务监控页面所需的后端接口。
4. 通过中间件或通用 View 能力采集审计信息。

## 边界约束

1. 不恢复已清理且未接入后端的历史 job、jobLog、logininfor 前端入口。
2. 不把任务实例、任务日志或任务监控重新放入 monitor 私有模型。
3. 日志表名前缀保持 `monitor_*`，避免历史表名错位再次出现。

## 演进方向

1. 监控能力可以增强为系统健康、接口耗时、异常统计和告警。
2. 与 `datatask` 集成时只读取任务实例摘要，不复制任务运行数据。
