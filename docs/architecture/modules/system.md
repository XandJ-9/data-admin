# system 模块架构

## 模块定位

`apps.system` 是平台基础管理模块，负责用户、角色、菜单、权限、部门、岗位、字典、通知和平台配置。

它提供全平台认证授权与菜单动态路由数据，是其他模块权限控制的基础。

## 核心职责

1. 维护用户、角色、菜单、部门、岗位、字典和配置。
2. 基于 `BaseModel` 提供通用审计字段和软删除字段。
3. 基于菜单 `perms` 和视图 `permission_map` 支持 action 级权限校验。
4. 通过 `initdata` 和 `sync_menu_data` 管理菜单种子数据。
5. 支持登录验证码、失败次数限流和 JWT 认证链路。

## 关键模型

- `User`
- `Role`
- `Menu`
- `Dept`
- `Post`
- `DictType`
- `DictData`
- `Config`
- `Notice`

## 边界约束

1. 业务模块只声明自己的权限映射，不在模块内重写系统权限模型。
2. 菜单 component 路径必须与前端真实页面一致，避免动态路由断链。
3. 修改菜单表单需要对后端详情做字段归一化，避免部分字段未回填。
4. `admin` 全量放行是当前兼容策略，普通角色必须走权限码校验。
5. 新增模块菜单时同步更新菜单种子和权限码，不只改前端路由。

## 演进方向

1. 持续收敛 action 权限码，避免写操作复用只读权限。
2. 将菜单种子作为前后端路由契约的核心维护点。
3. 强化配置项和敏感环境变量边界，减少硬编码配置。
