# 数据资产管理平台 - 总体架构设计

## 一、平台目标和定位

### 1.1 平台愿景

建立一个**统一的数据资产管理平台**，覆盖数据的整个生命周期：从数据源发现、元数据管理，到ETL开发、质量保证、任务监控和运维，再到数据服务暴露。

### 1.2 核心价值

| 价值维度 | 体现 |
|--------|------|
| **数据治理** | 统一的元数据管理、数据血缘追踪、质量保证 |
| **开发效率** | 可视化ETL配置、复用转换规则、版本管理 |
| **运维可靠性** | 完整的任务监控、自动告警、故障快速定位 |
| **成本透明** | 按数据源/租户/任务的成本分配 |
| **安全合规** | 数据血缘审计、敏感信息脱敏、访问控制 |
| **数据服务化** | 统一的数据查询接口、BI报表发布、数据API暴露 |

### 2.2 五大模块及其职责

#### 📦 **模块一：数据资产管理（Asset）**

**职责**：
- 统一的元数据管理和数据目录
- 完整的数据血缘追踪
- 数据影响分析

**核心功能**：
```
数据资产管理平台
├─ 【数据源管理】
│  ├─ 数据源连接配置
│  │  ├─ 支持多种数据库（MySQL、PostgreSQL、Oracle、SQLServer、SQLite等）
│  │  ├─ 主机、端口、用户名、密码配置
│  │  ├─ 自定义连接参数（JSON/KV格式）
│  │  ├─ 数据源启用/停用
│  │  └─ 备注和说明
│  ├─ 连接健康检查
│  │  ├─ 测试数据源连通性
│  │  ├─ 支持保存前验证
│  │  ├─ 支持修改前验证
│  │  └─ 连接失败诊断
│  ├─ 数据源管理
│  │  ├─ 数据源列表查询
│  │  ├─ 按名称、数据库类型、状态筛选
│  │  ├─ 数据源CRUD操作
│  │  ├─ 批量删除
│  │  └─ 创建时间、更新时间审计
│  └─ 元数据采集
│     ├─ 数据库列表查询（支持多库连接）
│     ├─ 表列表查询（支持按数据库筛选）
│     ├─ 字段列表查询（列名、类型、约束、默认值等）
│     ├─ 表注释和字段注释提取
│     ├─ 单表元数据采集
│     └─ 整库源数据异步采集
│
├─ 【元数据目录】
│  ├─ 表/字段级元数据
│  │  ├─ 表名、表注释、所属数据库
│  │  ├─ 字段编码、名称、类型
│  │  ├─ 非空约束、主键标识、默认值
│  │  ├─ 创建时间、更新时间
│  │  └─ 字段排序和分组
│  ├─ 数据统计信息
│  │  ├─ 表行数统计
│  │  ├─ 表大小统计
│  │  ├─ 最后更新时间
│  │  └─ 数据库名称和类型
│  └─ 数据质量评分
│     ├─ 表级质量评分
│     ├─ 异常字段标记
│     └─ 质量趋势展示
│
├─ 【血缘追踪】
│  ├─ 表级血缘
│  │  ├─ 上游表追溯（原始数据来源）

│  │  └─ 完整链路展示
│  ├─ 字段级血缘
│  │  ├─ 字段转换关系追踪
```

**当前实现功能**：
```
【数据源配置】
├─ 支持数据库类型
│  ├─ MySQL (主流关系型数据库)
│  ├─ PostgreSQL (高级关系型数据库)
│  ├─ Oracle (企业级数据库)
│  ├─ SQLServer (微软数据库)
│  ├─ SQLite (嵌入式数据库)
│  └─ 其他数据库（通过参数扩展）
├─ 数据源表单配置
│  ├─ 数据源名称 (必填，唯一)
│  ├─ 数据库类型 (下拉选择)
│  ├─ 主机地址 (支持域名和IP)
│  ├─ 端口号 (整数验证)
│  ├─ 数据库名称 (支持多库)
│  ├─ 用户名和密码 (加密存储)
│  ├─ 自定义参数 (JSON格式)
│  ├─ 启用状态 (0=正常, 1=停用)
│  └─ 备注说明 (500字以内)
└─ 安全特性
   ├─ 密码加密存储
   ├─ 修改时密码验证（是否变更）
   ├─ 连接信息审计
   └─ 访问权限控制

【元数据采集】
├─ 数据库列表查询
│  ├─ 按指定数据源查询所有数据库
│  ├─ 返回数据库名称列表
│  └─ 支持多数据库实例
├─ 表列表查询
│  ├─ 按数据源 + 数据库名查询表列表
│  ├─ 返回表名、表注释、数据库名
│  ├─ 支持创建时间和修改时间
│  └─ 支持大量表的加载（优化超时）
├─ 字段列表查询
│  ├─ 按数据源 + 表名查询字段列表
│  ├─ 返回字段序号、名称、类型、注释
│  ├─ 返回非空约束、主键标识、默认值
│  └─ 按字段顺序排列
└─ 异步采集（整库源数据）
   ├─ 支持后台异步任务
   ├─ 进度实时推送
   ├─ 支持采集任务取消
   ├─ 采集状态查询（百分比和文本说明）
   └─ 防止重复采集（任务锁定）
```

**数据模型**：
```
DataSource：数据源配置表
├─ name：数据源名称（唯一）
├─ db_type：数据库类型（mysql/postgres/oracle/sqlserver/sqlite等）
├─ host：主机地址
├─ port：端口号
├─ db_name：数据库名称
├─ username：用户名
├─ password：密码（加密存储）
├─ params：自定义参数（JSON格式）
├─ status：状态（0=正常, 1=停用）
├─ remark：备注说明
├─ del_flag：删除标记（软删除）
└─ 审计字段：create_by, update_by, create_time, update_time
```

**当前API端点**：
```
GET  /datasource/              - 数据源列表查询
GET  /datasource/{id}          - 数据源详情获取
POST /datasource/              - 创建数据源
PUT  /datasource/{id}          - 修改数据源
DELETE /datasource/{id}        - 删除数据源（批量以逗号分隔）

POST /datasource/{id}/test     - 测试指定数据源连通性
POST /datasource/test          - 根据请求体测试连通性（不保存）

POST /datameta/collection/databases  - 列表数据库
POST /datameta/collection/tables     - 列表业务表
POST /datameta/collection/columns    - 列表表字段
POST /datameta/collection/collect-table - 采集单表元数据
POST /datameta/collection/collect-async - 异步采集整库源数据
GET  /datameta/collection/status     - 查询采集进度
POST /datameta/collection/cancel     - 取消采集任务
```

**与其他模块的关系**：
```
Asset模块作为中心枢纽
      ↙     ↓     ↓     ↘
   ETL   Quality Task  Service
- 数据源配置：Asset → ETL (数据源连接配置继承)
- 元数据采集：Asset → 自动收集元数据
- 元数据展示：Asset提供表/字段元数据给所有模块
- 血缘同步：ETL生成血缘 → Asset记录和展示
- 质量规则：Quality绑定到Asset的表/字段
- 数据查询：Service查询时引用Asset的表元数据
```

**职责**：
- 完整的ETL任务配置和开发

**核心功能**：

```
ETL任务开发平台
├─ 【采集阶段】Extract → STG层
│  ├─ 数据源连接配置
│  ├─ 增量策略选择（全量/增量）
│  ├─ 字段映射配置
│  └─ 执行引擎选择（DataX）
│
├─ 【转换阶段】Transform → DWD/DWS/ADS层
│  ├─ 字段级转换
│  │  ├─ 字段映射
│  │  ├─ 类型转换
│  │  ├─ 清洗规则（null处理、格式化）
│  │  └─ 脱敏规则
│  ├─ 表级转换
│  │  ├─ 去重配置
│  │  ├─ 维度关联
│  │  ├─ 数据聚合
│  │  └─ 分割配置
│  └─ 流程级控制
│     ├─ 条件分支
│     ├─ 循环处理
│     └─ 错误处理
│
├─ 【加载阶段】Load → 各层数据仓库
│  ├─ 分区策略配置
│  ├─ 增量策略（追加/更新/合并）
│  ├─ 质量检查触发
│  └─ 元数据同步
│
├─ 【版本和控制】
│  ├─ 配置版本管理
│  ├─ 历史版本对比
│  ├─ 版本回滚
│  └─ 变更日志
│
└─ 【执行和测试】
   ├─ 单次执行（测试）
   ├─ 定时执行（生产）
   ├─ 手动触发
   └─ 执行日志查看
```

**数据流**：
```
外部数据源（多租户分库）
        ↓ [DataX执行器 - 高效并发]
STG缓冲层（按租户/日期分区，保留原始数据）
        ↓ [Spark SQL执行器 - 分布式]
ODS原始层（跨租户汇总、标准化、去重）
        ↓ [Spark SQL执行器]
DWD明细层（维度化、业务加工）
        ↓ [Spark SQL执行器]
DWS汇总层（聚合计算、指标生成）
        ↓ [Spark SQL执行器]
ADS应用层（应用专用、宽表、标签）
        ↓
数据服务/BI报表
```

## 五、核心流程设计

### 5.1 ETL任务执行流程

```
【任务执行的完整生命周期】

1. 【计划阶段】
   Scheduler检查是否该执行
   ├─ Cron时间到达？
   ├─ 事件触发？
   ├─ 依赖任务完成？
   └─ 黑名单日期排除？
   
2. 【准备阶段】
   ├─ 加载任务配置
   ├─ 验证数据源连接
   ├─ 初始化执行上下文
   └─ 生成执行ID

3. 【抽取阶段】(仅STG/ODS任务)
   DataX执行器
   ├─ 生成DataX JSON配置
   ├─ 生成多租户配置（STG任务特有）
   ├─ 连接源数据库
   ├─ 读取增量/全量数据
   ├─ 写入STG/ODS（Hive/HDFS）
   └─ 更新Hive分区元数据

4. 【汇总阶段】(仅ODS汇总任务)
   Spark SQL执行器
   ├─ 读取所有租户的STG数据
   ├─ 数据标准化处理
   ├─ 多租户去重
   ├─ 质量初检
   └─ 写入ODS表

5. 【转换阶段】(DWD/DWS/ADS任务)
   Spark SQL执行器
   ├─ 读取源表（ODS或前一层）
   ├─ 应用字段映射和清洗
   ├─ 应用维度关联（如需要）
   ├─ 应用聚合和计算（如需要）
   └─ 写入目标表

6. 【质量检查阶段】
   Quality模块
   ├─ 自动应用质量规则
   ├─ 检查数据完整性
   ├─ 检查数据一致性
   ├─ 生成质量报告
   └─ 失败时决定是否继续

7. 【元数据同步阶段】
   Asset模块
   ├─ 更新表的统计信息（行数、大小）
   ├─ 更新字段统计
   ├─ 同步血缘关系
   ├─ 记录最后更新时间
   └─ 计算质量评分

8. 【完成阶段】
   ├─ 记录执行结果
   ├─ 计算执行耗时
   ├─ 更新性能指标
   ├─ 触发下游任务（如有依赖）
   └─ 发送通知

9. 【故障处理】
   ├─ 异常捕获
   ├─ 错误日志记录
   ├─ 自动诊断
   ├─ 告警触发
   ├─ 重试判断
   └─ 人工介入预案
```

```
2. 【规则绑定】

   ├─ 选择规则应用的字段
   ├─ 设置规则阈值
   └─ 设置触发频率

3. 【自动检查】(在ETL执行后)
   ├─ 加载该任务关联的规则
   ├─ 对目标表执行规则检查
   ├─ 记录检查结果
   └─ 评估是否通过

4. 【问题发现】
   如果检查失败
   ├─ 生成违规数据样本
   ├─ 评估影响范围
   ├─ 评估严重程度
   └─ 触发告警

5. 【问题处理】
   ├─ 任务责任人收到告警
   ├─ 分析问题根因
   ├─ 决定修复策略
   │  ├─ 修复源数据（回溯源端）
   │  ├─ 修复ETL规则
   │  ├─ 修复质量规则（规则过严）
   │  └─ 隔离脏数据（标记为不可用）
   ├─ 执行修复
   └─ 验证修复效果

6. 【质量报告】
   ├─ 按表的质量评分
   ├─ 按时间的质量趋势
   ├─ 按规则的违反统计
   ├─ 关键数据表的质量预警
   └─ 质量改进建议

7. 【经验积累】
   ├─ 问题根因分析
   ├─ 规则优化建议
   ├─ 最佳实践文档
   └─ 类似问题预防
```

### 5.3 多租户数据隔离流程

```
【多租户分库场景的完整隔离方案】

1. 【数据源配置】
   每个租户的数据库连接独立配置
   ├─ 租户A: MySQL DB_A
   ├─ 租户B: Oracle DB_B
   └─ 租户C: PostgreSQL DB_C

2. 【任务配置】
   为每个租户创建独立的ETL任务
   ├─ task_user_a_stg (is_stg_task=True, tenant_id_field='A')
   ├─ task_user_b_stg (is_stg_task=True, tenant_id_field='B')
   └─ task_user_c_stg (is_stg_task=True, tenant_id_field='C')

3. 【抽取到STG】
   每个任务独立执行，数据写入STG
   ├─ 租户A的数据 → STG/user/tenant_id=A/ds=20260120/
   ├─ 租户B的数据 → STG/user/tenant_id=B/ds=20260120/
   └─ 租户C的数据 → STG/user/tenant_id=C/ds=20260120/

4. 【汇总到ODS】
   单个ODS汇总任务，读取所有租户STG数据
   ├─ 读取所有租户的STG/user数据
   ├─ 逐租户去重（Window分区by tenant_id）
   ├─ 数据标准化处理
   ├─ 质量检查（租户维度）
   └─ 写入ODS/user（可不分租户，但保留tenant_id字段）

5. 【成本分配】
   按STG分区统计成本
   ├─ 租户A的STG存储成本 = 统计 STG/user/tenant_id=A/ 的存储大小
   ├─ 租户B的STG存储成本 = 统计 STG/user/tenant_id=B/ 的存储大小
   ├─ 租户A的计算成本 = 该租户任务的CPU×时间
   └─ 租户A总成本 = 存储成本 + 计算成本

6. 【权限控制】
   ├─ 租户A的用户只能看到task_a_*的任务和执行日志
   ├─ 租户B的用户只能看到task_b_*的任务
   ├─ 租户A的用户不能查看任何租户B相关的血缘和元数据
   └─ 管理员可以看全部

7. 【故障隔离】
   某租户的数据问题不影响其他租户
   ├─ 租户A的STG→ODS失败
   ├─ 自动重试租户A的汇总任务
   ├─ 不重新抽取租户B和C的数据
   └─ 能快速恢复
```
