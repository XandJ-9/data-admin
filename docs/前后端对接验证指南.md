# 前后端对接验证指南

本文档提供详细的步骤来验证ETL系统前后端对接是否正常。

---

## 一、环境准备

### 1. 后端服务启动
```bash
cd backend
python manage.py runserver 0.0.0.0:8000
```

### 2. 前端服务启动
```bash
cd frontend
npm install  # 首次运行需要安装依赖
npm run dev
```

### 3. 确认服务状态
- 后端：http://localhost:8000
- 前端：http://localhost:80 (或配置的端口)
- API文档：http://localhost:8000/docs/

## 三、常见问题排查

### 问题1：API 404错误

**症状**：
```
PUT /api/dataetl/tasks/123 404 Not Found
```

**排查步骤**:
1. 检查后端URL配置：
   ```bash
   # 查看后端urls.py
   cat backend/apps/dataetl/urls.py
   ```

2. 确认路由前缀：
   ```python
   # backend/config/settings.py 或主路由文件
   path('api/dataetl/', include('apps.dataetl.urls')),
   ```

3. 使用curl测试API：
   ```bash
   curl -X GET http://localhost:8000/api/dataetl/tasks/
   ```

---

### 问题2：字段undefined

**症状**：页面显示 `undefined` 或空白

**排查步骤**:
1. 检查后端返回的字段名
2. 检查前端使用的字段名
3. 对比检查报告中的字段对照表

**示例**:
```javascript
// 后端返回
{
  "etlType": "data_integration"  // ✅ 正确
}

// 前端使用
{{ formData.taskType }}  // ❌ 错误，应该是 etlType
```

---

### 问题3：CORS错误

**症状**：
```
Access to XMLHttpRequest at 'http://localhost:8000' from origin 'http://localhost:80'
has been blocked by CORS policy
```

**解决方案**:
1. 配置Django CORS：
   ```bash
   pip install django-cors-headers
   ```

2. 在settings.py中添加：
   ```python
   INSTALLED_APPS = [
       ...
       'corsheaders',
   ]

   MIDDLEWARE = [
       'corsheaders.middleware.CorsMiddleware',
       ...
   ]

   CORS_ALLOW_ALL_ORIGINS = True  # 开发环境
   # 或者
   CORS_ALLOWED_ORIGINS = [
       "http://localhost:80",
       "http://127.0.0.1:80",
   ]
   ```

---

### 问题4：认证失败

**症状**：
```
401 Unauthorized
```

**排查步骤**:
1. 确认用户已登录
2. 检查Token是否有效
3. 检查请求头是否包含认证信息：
   ```
   Authorization: Bearer <token>
   ```

---

### 问题5：数据源列表为空

**症状**：任务表单中数据源下拉框无数据

**排查步骤**:
1. 检查数据源管理模块是否有数据
2. 检查API调用：
   ```
   GET /api/dataasset/datasources/
   ```
3. 检查前端API导入：
   ```javascript
   import { listDatasource } from '@/api/data/asset'
   ```
