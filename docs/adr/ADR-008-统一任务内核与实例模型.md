# ADR-008: 统一任务内核与实例模型

**Status**: Accepted  
**Date**: 2026-04-18

## Context

`docs/requirements/data-platform-function.md` 已被明确为平台最终实现目录，目标态要求平台以统一的 `Task / TaskDependency / TaskInstance` 为中轴，贯通：

1. 数据集成任务（DATA_SYNC）
2. 数据开发 SQL 任务（SQL_COMPUTE）
3. 依赖编排与实例运维

当前主干中：

- `dataasset` 仅有 `MetaCollectionTask`，只覆盖元数据采集。
- `datadev` 仅有 `DataDevScriptExecution`，属于脚本域局部执行日志。
- 仓库不存在统一任务定义、依赖关系与实例层模型。

如果继续按分散模型推进，将无法支撑后续的“数据搬运入仓 → SQL 开发 → DAG 编排 → 资产服务化”主链路。

## Decision

### 1. 新增 `apps.datatask` 作为统一任务中心

新增三个核心模型：

- `Task`：统一任务定义，承载 `task_type / task_config / schedule_type`
- `TaskDependency`：任务依赖边
- `TaskInstance`：任务运行实例

### 2. 先接入 `datadev`，不恢复旧 `dataetl`

首个接入方选择 `datadev`：

- `DataDevScript` 通过 `source_module='datadev.script' + source_record_id=<script_id>` 映射到统一 `Task`
- 每次脚本执行创建一条 `TaskInstance`
- `DataDevScriptExecution` 保留，但增加到 `TaskInstance` 的关联，作为脚本域视角的兼容执行日志

旧 `dataetl` 模块已下线，因此后续“数据集成”能力应直接接入 `datatask`，而不是恢复旧模块。

### 3. 保持血缘后置，但提前预留任务来源锚点

本阶段仍不实现自动血缘，但 `Task.task_config` 中要求保存来源脚本/数据源/版本等关键锚点，为后续从任务链反推资产血缘预留基础。

## Consequences

**优点**:

- 统一了任务定义与实例层，为后续调度、重试、依赖关系和运维拓扑提供稳定中心。
- `datadev` 可以逐步从“孤立执行日志”演进为“平台标准任务”。
- 后续数据集成、调度器、资产自动血缘都能围绕同一任务域扩展。

**缺点 / 风险**:

- 初期会存在 `MetaCollectionTask`、`DataDevScriptExecution` 与 `Task/TaskInstance` 并存。
- 当前只接通 `datadev`，还未形成完整 DAG 调度能力。
- `task_config` 首期仍以 JSON 承载运行配置，字段治理需后续继续收敛。

## Follow-up

1. 为数据集成能力补齐统一任务定义与实例接入。
2. 设计 `TaskDependency` 的前端配置与 DAG 运行规则。
3. 在统一任务链稳定后，再推进自动血缘来源建模与资产联动。
