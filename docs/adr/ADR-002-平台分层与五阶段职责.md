# ADR-002: 平台分层与五阶段职责

**状态**: Accepted  
**日期**: 2026-05-22

## 背景

项目已经形成数据源、数据集成、数据开发、任务运维、数据资产、数据服务、系统管理等多个模块。如果只按页面或表结构推进，容易出现职责漂移：任务中心侵入业务域、资产模块变成流程入口、数据集成承担数仓加工、数据开发反向处理源端连接。

因此需要固化平台分层和五阶段职责，用作需求拆分、模块设计、接口评审和页面组织的统一依据。

## 决策

平台按三层和五阶段组织。

### 三层结构

1. 业务模块层：`datasource`、`dataintegration`、`datadev`、`dataasset`、`dataservice`。
2. 平台运行层：`datatask`、`monitor`、`terminal`、`system`。
3. 执行与基础设施层：`executors`、`dbutils`、`common`、`utils`。

前端 `frontend` 作为 Web 入口按模块消费以上后端能力。

### 五阶段职责

#### 1. Connection & Discovery

归属模块：`apps.datasource`。

负责：

- 数据源定义、认证和连通性校验。
- 数据库、表、字段发现。
- 源数据采集任务定义。
- 向资产层提供源端元数据输入。

不负责：

- 贴源同步。
- 数仓加工。
- 任务调度内核。
- 资产语义治理。

#### 2. Data Integration

归属模块：`apps.dataintegration`。

负责：

- 源到目标的数据同步配置。
- 加载策略、写入方式和字段映射。
- 将数据集成任务发布到任务中心。
- 调用统一执行器完成贴源搬运。

不负责：

- 多表建模、指标计算、宽表加工。
- 任务依赖和调度内核。
- 资产语义治理。

#### 3. Data Development

归属模块：`apps.datadev`。

负责：

- SQL / Python 加工作业。
- 脚本版本管理。
- 数据模型和模型字段定义。
- 可发布到任务中心的开发作业。

不负责：

- 源端连接探查。
- 贴源同步语义。
- 平台调度内核。
- 对外 API 服务化。

#### 4. Orchestration & DataOps

归属模块：`apps.datatask`。

负责：

- 平台任务镜像。
- 任务依赖。
- 调度索引。
- 统一执行实例。
- 来源模块注册与执行分发。

不负责：

- 直接保存业务任务真源。
- 直接理解数据源采集、数据同步或脚本开发的业务细节。
- 资产模型和服务化语义。

#### 5. Assetization & Service

归属模块：`apps.dataasset`、`apps.dataservice`。

负责：

- 资产命名空间、资产主表、资产字段。
- 资产分类、生命周期、安全等级、业务域等语义。
- 数据接口、查询、报表和服务化消费。

不负责：

- 源端探查入口。
- 入仓执行编排。
- 数仓开发作业本身。
- 平台调度内核。

## 越界约束

1. 阶段归属优先于实现便利。
2. 前一阶段必须产出后一阶段可消费的标准化输入。
3. `datatask` 不得反向 import 来源模块内部执行细节。
4. `dataasset` 不得反向成为连接发现或任务编排入口。
5. 治理要求应嵌入正确阶段的流程，而不是额外造孤岛页面。

## 影响

1. 新需求评审时必须先判断所属阶段。
2. 模块文档应按该分层维护。
3. 如果某项实现短期放在非归属模块，必须标注收敛方向。
