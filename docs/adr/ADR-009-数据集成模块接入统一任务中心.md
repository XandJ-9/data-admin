# ADR-009: 数据集成模块接入统一任务中心

**Status**: Partially Superseded  
**Date**: 2026-04-18

> 时效性说明（2026-05-16）：本 ADR 关于 `DataIntegrationTask` 作为集成域配置模型并映射到统一 `Task` 的方向仍有效；但“尚无真实 `apps.dataintegration` 模块”“首期仅以 mock 打通执行链路”等内容已是历史阶段。当前主干已具备正式数据集成模块、显式发布到任务中心、发布快照优先执行与统一 `TaskInstance` 记录。

## Context

以 `ADR-011-平台五阶段职责划分规范` 为当前基线，平台需要具备“向导式同步表单 → 统一 `Task` → 执行实例”的数据集成能力。

制定本 ADR 时的仓库中：

- 已有 `apps.executors` 中的 `DataXExecutor` / `MockETLExecutor`
- 已有统一任务中心 `apps.datatask`
- 但没有真实可用的 `apps.dataintegration` 业务模块

这导致“数据搬运入仓（STG/ODS）”仍停留在架构空洞状态。

## Decision

### 1. 新增 `apps.dataintegration` 业务模块

模块职责是承载“数据集成任务配置表单”：

- 源数据源
- 目标数据源
- 源资产
- 目标表
- 加载类型 / 写入模式 / 执行器类型

### 2. 采用“配置模型 + 统一任务映射”策略

不直接让前端操作 `datatask.Task`，而是新增 `DataIntegrationTask` 作为集成域配置模型，并通过：

- `source_module='dataintegration.task'`
- `source_record_id=<integration_task_id>`

映射到统一 `Task`。

### 3. 历史阶段：首期执行链路先以 `mock` 打通

> 本节为早期落地策略，当前不再作为完整实现口径。当前数据集成任务已通过 `task_source.py` 接入 `datatask`，支持显式发布、发布快照优先执行，并统一记录到 `TaskInstance`。

由于现存 `DataXExecutor` 仍依赖旧 ETL 任务结构，暂不能直接挂到统一任务模型上，因此本阶段：

- 先支持 `mock` 执行器完成“创建任务 → 触发执行 → 产出 `TaskInstance`”闭环
- `datax` 仅保留配置入口与校验提示，待后续适配器补齐后再接通实际执行

## Consequences

**优点**:

- 第 2 步“数据集成入仓”首次有了真实业务模块承接。
- 与统一任务中心保持一致，不再重复造任务表。
- 能先用 mock 跑通端到端闭环，为后续接入真实执行器提供稳定接口。

**缺点 / 风险**:

- 首期曾未真正打通 DataX 执行；当前执行器能力以 `apps.executors` 与数据集成 source handler 的实际实现为准。
- `DataIntegrationTask` 与 `Task` 会短期并存，需持续维护配置同步。

## Follow-up

1. `DataIntegrationTask` 已作为数据集成配置模型落地，并通过 source handler 映射到平台任务。
2. 前端页面与菜单入口已落地，当前采用模块首页 + 任务列表 + 详情发布的产品口径。
3. 数据集成任务执行记录统一进入 `TaskInstance`，依赖编排继续按 `datatask.TaskDependency` 演进。
