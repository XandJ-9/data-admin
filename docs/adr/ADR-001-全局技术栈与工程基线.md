# ADR-001: 全局技术栈与工程基线

**状态**: Accepted  
**日期**: 2026-05-22

## 背景

项目需要一套稳定的数据管理平台技术基线，覆盖后端框架、前端框架、包管理、平台数据库、外部数据源适配和构建方式。该基线用于约束后续开发，不因单个功能偏好随意切换技术路线。

## 决策

### 后端

后端采用：

- Django 5.2
- Django REST Framework 3.16
- SimpleJWT
- Django Channels
- drf-spectacular
- Python 包管理使用 `uv`

新增后端能力默认按 Django App 拆分模块，API 优先沿用 DRF ViewSet、Serializer、Router 与当前项目的权限映射方式。

### 前端

前端采用：

- Vue 3.5
- Element Plus 2.10
- Vite 6
- Pinia
- JavaScript
- Node 包管理使用 `pnpm`

新增前端页面默认沿用 Vue 3 Composition API、Element Plus 和当前动态路由体系。不在常规业务迭代中切换 UI 框架，也不把 TypeScript 改造混入功能开发主线。

### 平台数据库

平台自身数据库策略：

- 本地开发和测试默认使用 SQLite。
- 生产环境使用 PostgreSQL 或 MySQL。
- `SECRET_KEY`、`DEBUG`、`ALLOWED_HOSTS`、数据库连接、Channel Layer 等敏感配置必须支持环境变量覆盖。

SQLite 只用于本地和低并发测试，不作为生产数据库方案。

### 外部数据源

外部数据源统一通过 `apps.dbutils` 访问，当前支持：

- MySQL / MariaDB
- PostgreSQL
- SQLite
- StarRocks
- Presto / Trino

新增数据库类型时，扩展 `dbutils` 执行器和工厂，不在业务模块中直接写数据库驱动逻辑。

### 构建与启动

后端常用命令：

```bash
cd backend
uv sync
uv run python manage.py migrate
uv run python manage.py runserver 0.0.0.0:8000
```

前端常用命令：

```bash
cd frontend
pnpm install
pnpm dev
pnpm build
```

`pnpm build` 与 `pnpm build:prod` 都应保持为生产构建入口。

## 影响

1. 后续新增模块默认使用现有 Django / DRF / Vue / Element Plus 技术体系。
2. 包管理统一为 `uv` 和 `pnpm`，不再混用 pip、npm、yarn。
3. 数据库访问能力向 `dbutils` 收敛，避免业务模块散落驱动代码。
4. 构建工具保持 Vite，不因局部依赖问题随意切换构建体系。
