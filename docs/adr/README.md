# 架构决策记录（ADR）

本目录用于存放项目的架构决策记录（Architecture Decision Records）。

## 当前基线

1. `ADR-011-平台五阶段职责划分规范.md`
	- 平台阶段职责边界与越界约束（当前模块归属判断基线）。
2. `ADR-012-统一任务定义与执行实例边界规范.md`
	- 业务模块任务定义、`Task` 平台镜像、`TaskInstance` 唯一执行实例的协作基线。
3. `ADR-010-后端平台分层与模块职责重构.md`
	- 后端层级关系与模块职责分层（架构落位基线）；其中 `datasource` 接入任务中心、`TaskInstance` 单一执行中心等后续演进以 ADR-012 和当前状态文档为准。

## 背景决策

以下 ADR 当前仍有效，但一般只在涉及对应基础设施时阅读：

1. `ADR-001-技术栈选型.md`
	- 后端、前端、认证、API 文档与数据库支持范围的基础选型。
2. `ADR-003-包管理器选型.md`
	- 后端 `uv` 与前端 `pnpm` 的包管理约定。
3. `ADR-004-数据库选型.md`
	- 平台元数据库与外部数据源访问边界。
4. `ADR-005-Terminal-PTY架构.md`
	- Web Terminal 的 PTY + WebSocket 交互架构。
5. `ADR-007-数据资产标准模型重构.md`
	- `dataasset` 规范资产模型与兼容模型并存的迁移策略。

## 历史阶段口径

以下 ADR 不作为当前实现的直接口径，只用于追溯决策背景：

1. `ADR-006-数据开发模块架构决策.md`
	- 数据开发模块的早期形态仍可参考，但“调度与依赖由既有 ETL 能力负责”“ScriptExecution 作为脚本域执行记录”等判断已被 ADR-012 覆盖。
2. `ADR-008-统一任务内核与实例模型.md`
	- 统一任务内核的引入背景仍有效，但 `DataDevScriptExecution` 长期兼容并存的判断已被 ADR-012 覆盖。
3. `ADR-009-数据集成模块接入统一任务中心.md`
	- 数据集成模块接入统一任务中心的方向仍有效，但“尚无真实 dataintegration 模块”“首期仅 mock 打通”等内容已是历史阶段。
4. `ADR-010-后端平台分层与模块职责重构.md`
	- 分层原则仍有效；关于 `datasource` 暂不接入 `datatask`、Phase 2 待补齐采集任务定义等阶段性内容已由当前主干实现和 ADR-012 收敛。

## 已删除旧 ADR

1. `ADR-002-ETL执行器架构.md`
	- 原文只描述已下线的 `apps.dataetl` 模块内部执行器目录，当前有效执行器实现已迁移到 `apps.executors`，历史过程见 `docs/archive/`。

## 编写规则

1. 每个重要架构决策单独一份 ADR，编号递增，如 `ADR-001-数据库选型.md`。
2. 若决策变化，通过新 ADR 覆盖，并在目录与正文中注明“替代关系”或“部分过时范围”，完全无用的就旧文档可以删除。
3. 需求、模块设计、接口调整若涉及边界变化，先更新 ADR 再落代码。
