## 使用规则

1. ADR 记录跨模块、长期有效、会影响后续开发路径的决策。
2. 模块内部设计细节优先写入 `docs/architecture/modules/`。
3. 日常流程、命令和协作规范写入 `docs/developments/`。
4. 反复出现的问题写入 `docs/troubleshooting/`。
5. 决策变更时直接更新当前 ADR 或新增下一号 ADR，不保留会误导后续开发的旧正文。
