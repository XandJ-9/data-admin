# Bug 修复提示词

适用场景：页面报错、接口 500、测试失败、构建失败、权限异常、数据不一致或线上回归。

```text
请按故障优先流程修复以下问题。

问题现象：
<粘贴报错信息、接口路径、页面路径、复现步骤或测试失败输出>

影响范围：
<说明影响的模块、页面、接口或用户操作；不确定时写“待定位”>

修复要求：
1. 先应用 docs/prompts/01-project-rules.md 的固定规则。
2. 先复现或定位根因，不做无关优化。
3. 如果涉及模块职责或任务执行链路，先应用 docs/prompts/04-module-boundary-check.md。
4. 修复必须保持最小必要改动。
5. 如果涉及接口字段，确认前端 API、后端 serializer/view、页面消费字段一致。
6. 如果涉及权限，确认后端 permission_map、菜单 perms、前端 v-hasPermi 一致。
7. 如果涉及数据库唯一约束、软删除或迁移，确认历史数据兼容与迁移安全。
8. 修复后补充或更新回归测试，至少覆盖本次复现路径。
9. 运行最小必要测试。
10. 同步 docs/requirements/active_tasks.md 和 docs/changelog.md。

输出要求：
- 根因：说明问题为什么发生。
- 修复：说明改了哪些文件和关键逻辑。
- 验证：列出运行的测试命令和结果。
- 风险：说明仍未覆盖或需要人工复核的点。
```

常用补充约束：

```text
不要把临时兜底当成长期方案；如果必须加兼容逻辑，请在代码和文档中说明收敛方向。
```

```text
不要通过放宽权限、吞掉异常、删除校验来绕过故障；必须保留项目安全和模块边界。
```
